# 架構與安全設計

## 靜態 PWA 架構

本專案會輸出為 Vite 靜態網站，可透過 GitHub Pages 部署。瀏覽器端使用 Firebase Authentication 登入、Cloud Firestore 儲存委託單，並使用 Firestore 的 IndexedDB 持久化快取。Firestore 的網頁端持久化快取可在離線時讀寫已快取資料，並在恢復連線後自動同步本機變更；同一文件的衝突採最後寫入為準，因此介面會顯示最近同步時間與未同步提示。[Firebase 離線資料文件](https://firebase.google.com/docs/firestore/manage-data/enable-offline)

| 層級 | 採用方式 | 職責 |
| --- | --- | --- |
| 前端 | React、TypeScript、Tailwind CSS | 儀表板、看板、表單、付款計算與進度操作。 |
| 身分驗證 | Firebase Authentication 的電子郵件／密碼登入 | 第一版不提供公開註冊；僅由 Firebase Console 預先建立繪師帳號。 |
| 雲端資料 | Cloud Firestore | 儲存使用者帳號下的委託單、狀態歷程及未來的分享權杖中繼資料。 |
| 本機資料 | Firestore Persistent Local Cache（IndexedDB） | 可離線新增、修改、查詢，恢復連線後由 SDK 自動補登。 |
| 安裝與快取 | Web App Manifest 與 Service Worker | 提供可安裝、離線開啟的應用程式殼層。 |
| 部署 | GitHub Pages | 以 GitHub Actions 建置 `dist` 靜態檔，不依賴 Manus 平台。 |

## 資料路徑與存取控制

委託資料會寫入 `artists/{uid}/commissions/{commissionId}`。前端只使用登入者的 `uid` 建立資料路徑；Firestore Security Rules 必須同時要求使用者已登入，且其電子郵件為繪師核准帳號，才可讀寫自己的資料。前端的允許電子郵件檢查只用於使用體驗，**真正的存取限制必須在 Firestore Security Rules 實作**。

> 在啟用網頁端持久化快取前，應只在繪師信任的私人裝置使用，因為快取可能跨工作階段保留資料。[Firebase 離線資料文件](https://firebase.google.com/docs/firestore/manage-data/enable-offline)

## 限時分享結構

第一版先在每張委託單儲存 `shareEnabled`、`shareTokenHash` 與 `shareExpiresAt`，但不會把委託人聯絡方式、報價、付款、設定資料或內部備註暴露給公開頁面。正式啟用公開分享時，應新增受 Security Rules 與後端驗證保護的唯讀資料投影，避免純前端以明文權杖直接查詢完整委託單。

## Firebase 專案設定需求

| 設定項目 | 用途 |
| --- | --- |
| Web App 組態 | 提供 API Key、Auth Domain、Project ID、Storage Bucket、Sender ID 與 App ID 給靜態網站初始化 Firebase。 |
| Authentication | 啟用「電子郵件／密碼」登入；在 Console 預先建立唯一繪師帳號，不在程式提供註冊入口。 |
| Firestore | 建立 Production Mode 資料庫並套用專案附帶的安全規則。 |
| Authorized Domains | 加入 GitHub Pages 正式網域、測試網域及日後自訂網域。 |
| GitHub Actions Variables／Secrets | 將 Firebase Web App 組態與核准帳號設定在 GitHub repository secrets，避免直接提交到版本庫。 |
